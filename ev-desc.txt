EV-52MediumPython
scan() stats the entire plugin virtualenv on every call
worker.py:74 — for f in plugin_dir.rglob("*.py")
_get_plugin_mtime walks the plugin directory recursively, and the plugin's own .venv lives inside it. For the shipped example that is 501 Python files inside a 1936-entry tree, giving a 45 ms cache-hit cost for a single plugin. With a handful of plugins carrying real dependency trees — pandas, torch — this becomes seconds per scan, all of it stat calls on files that can never be plugin source.
Fix Prune .venv, wheels, __pycache__ and dotted directories from the walk. A plugin's own sources are what the cache key is for.
