EV-44LowC++C
bytes returned by a plugin decode three different ways
evoker_client.cpp:340 — base64 is returned as raw text
plugin returns b"\x00\x01\xff binary" Python host b'\x00\x01\xff binary' (bytes, correct) Rust host Base64([0, 1, 255, 32, 98, ...]) (typed, correct) C++ / C "\nAAH/IGJpbmFyeQ==\n" (undecoded, with the newlines XML-RPC pads it with)
The C++ parser treats <base64> as an opaque string, so a C or C++ host receives a whitespace-padded base64 blob it must know to strip and decode. Nothing documents this. The same applies to <dateTime.iso8601>, handled by the same branch.
Fix Decode into nlohmann::json::binary (which round-trips through the C ABI as a byte array), or at minimum strip the padding whitespace and document that the value is base64.
EIsolation, as claimed and as built
Evoker's stated first principle is "True Process Isolation … Plugins are treated as untrusted worker nodes." The host boundary genuinely holds. The plugin-to-plugin boundary does not exist.
