EV-58MediumPython
Failed coercion silently hands the plugin a value of the wrong declared type
worker.py:145–146 — except (ValueError, TypeError): pass # Let the plugin handle the error
action: def echo_int(v: int) -> int call: invoke("echo_int", {"v": "notanint"}) result: 'notanint' (a str, delivered to a parameter declared int, no error)
The coercion layer exists precisely because native hosts cannot always express Python types, so a host is entitled to trust that a parameter the manifest calls int arrives as an int. When the conversion fails the value is passed through unchanged and the plugin — which may well not type-check — proceeds on a string. The comment says "let the plugin handle the error", but nothing tells the plugin an error occurred.
Fix Raise a fault naming the parameter, its declared type, and the value received. A host can act on that; a silently wrong type it cannot.
