Plugin site-packages are inserted into sys.path and never removed
manager.py:149 inserts at index 1; only index 0 is popped at :158
load_plugin pushes the plugin directory at index 0 and its venv's site-packages at index 1, then pops only index 0 in the finally. Every plugin's dependencies therefore accumulate permanently on the worker's path, visible to every plugin loaded afterwards. The architecture guide states the opposite: "sys.path.pop(0) cleans up the plugin directory from the search path to prevent namespace collisions between distinct plugins."
The collision detector added last round only catches packages that are already imported from a different location — it cannot see a merely-installed package, so plugin B silently inherits plugin A's dependency tree whenever B has not imported the name itself. There is also a smaller ordering hazard: if a plugin mutates sys.path[0] during exec_module, the pop(0) removes the wrong entry.
Fix Record the exact strings inserted and remove those specific entries in the finally, or accept the accumulation deliberately and correct the documentation. Popping by value rather than by index also fixes the ordering hazard.
