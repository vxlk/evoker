EV-42MediumAll
Carriage returns are silently rewritten to newlines in every host
XML 1.0 §2.11 line-ending normalisation, unmitigated in all four clients
XML parsers normalise \r\n and lone \r to \n unless the character is escaped as &#13;. No Evoker client escapes it, so any string containing a carriage return arrives changed. Windows text files, HTTP headers, clipboard payloads and CSV fragments all carry \r\n.
Python host 'a\r\nb' -> 'a\nb' *** CHANGED *** C++ host plugin repr() = 'a\nb' (sent 'a\rb') Rust host plugin repr() = 'a\nb' (sent 'a\rb') control 'a\nb', 'a\tb', 'café 中文 😀', 'a&<>"\'b' all round-trip intact
Unicode is otherwise clean — emoji, CJK, combining accents and regional-indicator pairs all survive unchanged, in every binding. The corruption is specific to \r.
Fix Escape \r as &#13; in each client's serialiser (a one-line addition to xmlrpc_escape in C++), and note the behaviour in the wire-contract documentation.
